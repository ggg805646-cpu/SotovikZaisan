# Подключение админки Sotovik Zaisan

Админка расположена по адресу `https://ggg805646-cpu.github.io/SotovikZaisan/admin.html` после публикации файлов. Вход разрешён только двум пользователям, которых владелец вручную добавит в `admin_users`.

## 1. Создать проект Supabase
1. Откройте https://supabase.com/ и войдите/создайте аккаунт.
2. Создайте проект (регион выберите ближайший доступный; пароль базы сохраните у себя).
3. В проекте откройте **Project Settings → API** (или Connect): скопируйте **Project URL** и публичный **anon/publishable key**.
4. В файле `js/supabase-config.js` замените `ВСТАВЬТЕ_PROJECT_URL` и `ВСТАВЬТЕ_ANON_PUBLIC_KEY` своими значениями.
   - В файл разрешено вставлять только URL проекта и публичный anon/publishable key.
   - НИКОГДА не вставляйте `service_role`, `secret`, пароль базы данных или личные токены.

## 2. Создать таблицы и правила доступа
1. В Supabase откройте **SQL Editor → New query**.
2. Скопируйте весь файл `supabase-setup.sql`, вставьте и нажмите **Run**.
3. Это создаст таблицы, политики доступа и публичное хранилище фотографий. Чтение товаров публичное, изменение — только для пользователей из `admin_users`.

## 3. Создать два аккаунта
1. Откройте **Authentication → Users → Add user → Create new user**.
2. Создайте аккаунт для себя и отдельный аккаунт для папы. Используйте разные пароли; не включайте публичную регистрацию пользователей.
3. Скопируйте UUID каждого пользователя из списка Users.
4. Откройте **SQL Editor** и выполните запрос, заменив оба UUID:

```sql
insert into public.admin_users (user_id) values
('UUID_ТВОЕГО_АККАУНТА'),
('UUID_АККАУНТА_ПАПЫ');
```

Только эти две учётные записи получат право добавлять, изменять и удалять товары. Не публикуйте UUID вместе с паролями; UUID сам по себе не является паролем.

## 4. Загрузить файлы в GitHub
1. Распакуйте обновлённый архив.
2. Откройте репозиторий `ggg805646-cpu/SotovikZaisan`.
3. Загрузите содержимое папки проекта в корень репозитория, заменив старые файлы. Важно: не загружайте папку `sotovik_work` целиком внутрь репозитория — `index.html` должен остаться в корне.
4. Дождитесь завершения GitHub Pages (обычно несколько минут).
5. Откройте сайт и проверьте каталог. Затем откройте `/admin.html` и войдите.

## 5. Как работать с товарами
- **Добавить товар** → заполнить название, категорию, цену, наличие, описание → выбрать фотографии → сохранить.
- **Изменить** → изменить нужные поля → сохранить.
- **Удалить** → подтвердить удаление.
- Изображения сохраняются в Supabase Storage, а не в GitHub. Поэтому новые фотографии не требуют повторной публикации.
- Каталог сайта загружает облачные данные. Если Supabase временно недоступен или не настроен, сайт использует старый локальный каталог из `js/products.js`.

## Важные замечания
- При первом запуске таблица `products` пустая. Чтобы перенести исходные товары сайта в облако, после выполнения SQL запустите импорт один раз через SQL Editor: для этого подготовлен файл `seed-products.sql`.
- Админка не поддерживает удаление старых файлов фотографий из Storage при удалении/замене товара; запись товара удаляется, а старые фото остаются в хранилище. Их можно чистить отдельно в Storage.
- GitHub Pages — публичный сайт. `admin.html` не является секретной страницей; безопасность обеспечивается входом Supabase и RLS-политиками на сервере.
